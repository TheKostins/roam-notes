# Проверка заметок

Аргумент: пусто (спросить), `today`, `all`, либо ссылки на заметки (заголовок / префикс UUID / файл).
Контракт формата и жёсткие правила — в `CLAUDE.md` vault. Главное: **ни одной правки без одобренного номера**.

## Процесс

### 1. Что проверять
```bash
python3 tools/roam.py pending
```
Без аргумента — показать список и спросить, какие брать; заметка, которую пользователь ещё дописывает, в проверку не идёт. `today` = `pending`, созданные сегодня (`list --since <сегодня> --status pending`). Заглушки (`backfill`) не проверяются — только упоминаются. За один проход разумно 5–8 заметок; больше — разбить на партии по теме.

### 2. Снимок
```bash
python3 tools/roam.py guard <refs>
git status --short
```
`guard` сам спрашивает Emacs о несохранённых буферах; если пишет, что сервер недоступен, — попросить пользователя сохранить буферы (`C-x s`). Если рабочее дерево грязное — `git add -A && git commit -m "audit: snapshot"`.

### 3. Детерминированная часть
```bash
python3 tools/roam.py lint <refs>
python3 tools/roam.py spell <refs>
```
Это кандидаты, а не вердикты: `spell` не знает терминов («подграфик», «Минковского», «гильбертовость»), M11 срабатывает на полуинтервалах.

### 4. Содержательная часть — по каждой заметке
```bash
python3 tools/roam.py context <ref>
```
Прочитать бандл целиком: тело, формулировки связанных заметок, бэклинки, упоминания, прошлые отклонения. Для теорем и определений курса найти место в конспекте и **прочитать страницу визуально** (Read с `pages`, номера физические):
```bash
python3 tools/roam.py grep-pdf metopt '<ключевое слово>'
```

Рубрика, по порядку:
1. **Формулировка.** Область определения и значений каждой функции; кванторы и их порядок; все ли условия названы (выпуклость множества, дифференцируемость, симметричность…); определён ли каждый символ; совпадает ли тип заметки с тегом (`definition` на теореме — находка).
2. **Доказательство.** Каждый переход обоснован; каждое условие теоремы где-то использовано (если нет — лишнее условие или дыра); нет круга; оба направления `⇔` доказаны; индукция имеет базу; размерности и транспонирования согласованы.
3. **Согласованность** с определениями из связанных заметок (обозначения, соглашения вроде `⟨x; y⟩`).
4. **LaTeX / экспорт**: находки lint M*, плюс то, что lint не видит (пропущенный индекс, `x_+th`, не тот символ).
5. **Русский язык**: подтверждённые опечатки из `spell`, согласование, пропущенные слова. Стиль автора не переписывать.
6. **Связи**: «кандидаты в ссылки» и «несвязанные упоминания» из `context`; понятие, используемое без заметки → предложить backfill-заглушку; теги.
7. **Атомарность**: заметка содержит два самостоятельных утверждения → предложить разделить (только предложение).
8. **Идеи** (класс I): интуиция, пример, контрпример, «зачем это условие». Не больше двух на заметку.

Для доказательства длиннее ~15 строк — запустить субагента со свежим контекстом (Agent, general-purpose): дать только текст заметки и формулировки связанных заметок, задача: «Проверь доказательство шаг за шагом. Перечисли шаги, которые не следуют из предыдущих или из условий, и условия, которые не использованы. Ничего не исправляй». Его выводы перепроверить самому, прежде чем включать в отчёт.

Ошибкой (E/G) считать только то, что можешь обосновать математически. Сомневаешься — пиши как вопрос с уверенностью «низкая». Расхождение с конспектом без математической ошибки — класс D, обе формулировки рядом.

### 5. Отчёт
Записать в `.audit/reports/YYYY-MM-DD-HHMM-audit.md` и показать в чате. Сквозная нумерация через все заметки.

```markdown
# Проверка 2026-09-18 21:10 — 4 заметки (snapshot abc1234)
Сводка: E 2 · G 1 · L 3 · S 4 · C 2 · D 1 · I 2 · M 1 (11 правок)

## Дифференциальный критерий выпуклости (20260918132958-….org)

### 1 [E · уверенность высокая] Неверная область значений
L7: `$f: E \rightarrow \R^n$`
Скалярное неравенство ниже требует вещественнозначной функции; в связанном определении выпуклой функции тоже `\R`.
- было:  `Пусть $f: E \rightarrow \R^n$ --`
+ стало: `Пусть $f: E \rightarrow \R$ --`

### 7 [S] Нет заметки для понятия «градиент»
Используется в L8, L50. Предлагаю заглушку: «Градиент», теги `metopt,definition,backfill`. (требуется ответ)

## Механика
### 12 [M] 11 правок в 6 файлах: H06 хвостовые пробелы ×5, H04 ×1, T02 порядок тегов ×4, X02 ×1
(применяется через `roam.py fix`; diff — по запросу)
```

Классы: **E** математическая ошибка · **G** пропущенное условие / дыра в доказательстве · **L** LaTeX, экспорт-безопасность · **S** ссылки, теги, недостающая заметка · **C** ясность, русский язык · **D** расхождение с конспектом (информативно, без авто-правки) · **I** идея · **M** механика (один пункт на весь отчёт).

Требования к находке: номер, класс, уверенность (высокая/средняя/низкая), строка + точная цитата, суть в 1–2 предложениях, **точные** `было/стало` (минимальная правка, пригодная для Edit). Для I и для всего, где нужен текст автора, — пометка «требуется ответ», без `было/стало` или с черновиком.

В конце отчёта — подсказка по ответу:
`применить 1,3,5-8` · `всё кроме 4` · `3: <свой вариант>` · `отклонить 2,9` · остальное считается отложенным.

**После отчёта — стоп. Ждать ответа пользователя.**

### 6. Применение
Только названные номера.
1. Для каждой затронутой заметки: `python3 tools/roam.py guard <ref> --expect-hash <file_hash из context>`. Отказ → перечитать файл, пересобрать правку, при конфликте спросить.
2. Правки — через Edit, точно как в `стало` (или вариант пользователя). Механика — `python3 tools/roam.py fix <refs> --rules <одобренные> --apply`.
3. Одобренные заглушки: `printf 'backfill\n' | python3 tools/roam.py new --title "…" --tags metopt,definition,backfill --body-file -`, затем вставить id-ссылку в заметку, если это было частью находки.
4. `python3 tools/roam.py lint <затронутые>` — новых E/W быть не должно; `git diff --stat`.

### 7. Фиксация
```bash
git add -A && git commit -m "audit: apply #1,3,5-8 (<кратко>)"
python3 tools/roam.py state mark <refs> --report <имя отчёта> --open <число отложенных>
python3 tools/roam.py state dismiss <ref> --fp <fp>                    # отклонённая lint-находка
python3 tools/roam.py state dismiss <ref> --category C --text "…"      # отклонённая содержательная
git add -A && git commit -m "audit: state"
```
`state mark` — только для заметок, по которым пользователь ответил (применил или отклонил); заметка с отложенными находками тоже помечается, число отложенных идёт в `--open`. Отклонённое больше не поднимать: `context` показывает прошлые отклонения.

Обновить базу org-roam: `python3 tools/roam.py sync` (при недоступном сервере — напомнить `M-x org-roam-db-sync`). Предложить следующий шаг: `/notes-lecture` или `/notes-anki`.
